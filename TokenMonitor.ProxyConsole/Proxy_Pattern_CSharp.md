# Техническая документация: Локальный Прокси-Сервер TokenMonitor.Proxy

Локальный гибридный прокси-сервер на базе **ASP.NET Core Minimal API** и веб-сервера **Kestrel** [cite: 1]. Прокси спроектирован для перехвата, мониторинга и маршрутизации трафика между клиентскими приложениями (например, средами разработки IDE) и удаленными ИИ-платформами [cite: 1].

---

## 1. Архитектура и Режимы Работы

Прокси-сервер разворачивается локально на порту `8181` [cite: 1] и работает в двух независимых режимах в зависимости от типа входящего HTTP-запроса:

| Режим / Метод | Назначение | Механизм работы | Доступ к телу (Body) |
| :--- | :--- | :--- | :--- |
| **HTTP Проксирование**<br>(GET, POST, и др.) | Пересылка обычных веб-запросов и API-вызовов [cite: 1]. | Запрос полностью вычитывается в буфер, логируется в консоль и дублируется на целевой сервер через `HttpClient` [cite: 1]. | **Да**. Текст запроса доступен в сыром виде, что позволяет анализировать промпты и считать токены [cite: 1]. |
| **HTTPS Туннелирование**<br>(CONNECT) | Организация сквозного защищенного канала для SSL/TLS трафика [cite: 1]. | Прокси перехватывает сырой сетевой сокет, подключается к удаленному хосту по TCP и осуществляет двусторонний обмен байтами [cite: 1]. | **Нет (без MITM)**. Трафик внутри туннеля зашифрован. Прокси видит только метаданные соединения и факт подключения [cite: 1]. |

---

## 2. Пошаговый Разбор Сетевого Лога

Предоставленный лог наглядно демонстрирует полный жизненный цикл одного HTTPS-соединения:

1. `Executing endpoint 'Fallback {*path:nonfile}'`
   Kestrel перехватил входящий запрос. Так как явные маршруты (роуты) не заданы, управление передается в универсальный обработчик `MapFallback` [cite: 1].
2. `[Proxy] Создание HTTPS туннеля к: opencode.ai:443`
   Клиентское приложение (IDE) прислало запрос с HTTP-методом `CONNECT` [cite: 1]. Прокси успешно распарсил целевой хост и порт [cite: 1].
3. `Request finished HTTP/1.1 CONNECT http://opencode.ai:443 - 200 - - 555.2469ms`
   Прокси ответил клиенту статус-кодом `200 Connection Established` [cite: 1], после чего в течение **555.24 миллисекунд** происходил непрерывный двусторонний обмен зашифрованными данными между клиентом и `opencode.ai`. После закрытия сессии туннель уничтожился [cite: 1].

## 3. Детальный Анализ Компонентов Кода

### Инициализация и Конфигурация Веб-Хоста
Код написан с использованием современного синтаксиса верхнего уровня (Top-Level Statements) [.NET 6+]. Веб-сервер Kestrel принудительно настраивается на прослушивание только локального интерфейса:
```csharp
builder.WebHost.ConfigureKestrel(options =>
{
    options.ListenLocalhost(8181);
});
```
Это гарантирует безопасность, исключая доступ к прокси-серверу из внешней сети [cite: 1]. Для оптимизации работы с сокетами и поддержки механизма Connection Pooling для HTTP-запросов создается единый экземпляр `HttpClient` (`forwarderClient`) [cite: 1].

### Блок HTTPS Туннелирования (Метод CONNECT)
При фиксации метода `CONNECT` активируется низкоуровневая логика работы с сетью [cite: 1]:
* **Извлечение сокета:** Kestrel абстрагирует сетевой уровень, поэтому для получения доступа к сетевому потоку используется фича контекста `IConnectionSocketFeature` [cite: 1]. Если она недоступна, выполнение прерывается [cite: 1].
* **Создание моста данных:** Прокси инициирует асинхронное TCP-подключение к удаленному ИИ-серверу через `TcpClient` [cite: 1]. После этого запускаются две параллельные задачи копирования потоков [cite: 1]:
  ```csharp
  var clientToTarget = clientStream.CopyToAsync(targetStream);
  var targetToClient = targetStream.CopyToAsync(clientStream);
  ```
* **Мягкое закрытие (Graceful Shutdown):** Использование `Task.WhenAny` позволяет определить, какая из сторон первой завершила передачу данных [cite: 1]. Код не сбрасывает соединение жестко, а отправляет сигнал `SocketShutdown.Send`, позволяя второй стороне корректно дочитать оставшиеся в буфере байты [cite: 1].

> ⚠️ **Важное ограничение:** Из-за природы сквозного TLS-туннелирования, данный блок кода **физически не может** перехватить текстовое содержимое (тело запроса) при работе по HTTPS [cite: 1]. Весь трафик внутри `NetworkStream` зашифрован ключами удаленного сервера [cite: 1].

### Блок HTTP Проксирования и Мониторинга
Если клиент отправляет стандартный незашифрованный HTTP-запрос, код выполняет инспекцию данных [cite: 1]:
* **Многократное чтение потока:** Строка `context.Request.EnableBuffering()` переводит поток тела запроса в режим поддержки буферизации [cite: 1]. Это критически важно: если вычитать тело через `StreamReader` для вывода в консоль, позиция потока сбросится в конец. Установка `context.Request.Body.Position = 0` позволяет повторно передать это же тело запроса дальше по сети [cite: 1].
* **Репликация заголовков:** Заголовки оригинального запроса переносятся в новый `HttpRequestMessage` [cite: 1]. Код учитывает разделение на стандартные заголовки запроса и заголовки контента (такие как `Content-Type`) [cite: 1].

## 4. Архитектурный Анализ

### Преимущества реализации
1. **Асинхронность (Non-blocking I/O):** Все операции выполняются через `async/await` [cite: 1]. Это позволяет серверу обрабатывать сотни параллельных туннелей без блокировки потоков и утечки ресурсов.
2. **Легковесность:** Minimal API исключает накладные расходы на тяжеловесные контроллеры и MVC-фильтры.
3. **Безопасность «из коробки»:** Привязка к `ListenLocalhost` защищает сервер от использования извне в качестве открытого релея (Open Relay) [cite: 1].

### Недостатки и рекомендации по улучшению
1. **Слепая зона HTTPS:** Прокси логирует только HTTP-запросы [cite: 1]. Современные ИИ-клиенты по умолчанию работают через HTTPS (`https://opencode.ai`), из-за чего логирование токенов в текущей архитектуре работать для них не будет (запросы пойдут через шифрованный метод `CONNECT`) [cite: 1]. *Решение: Внедрение SSL MITM (подмена сертификатов) средствами библиотеки `Telerik.NetworkProxy` или через кастомный `SslStream` с локальным доверенным CA-сертификатом.*
2. **Парсинг портов:** Строка `int.Parse(parts[1])` уязвима к ошибкам, если в строке подключения окажется некорректный формат [cite: 1]. Надежнее использовать `int.TryParse`.
3. **Заголовки `Hop-by-Hop`:** Код слепо копирует абсолютно все заголовки [cite: 1]. Некоторые транспортные заголовки (например, `Keep-Alive`, `Transfer-Encoding`, `Connection`) по стандарту HTTP не должны пересылаться дальше прокси-сервером, так как они относятся исключительно к текущему узлу связи.
